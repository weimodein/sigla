No live database, deployment, device, email delivery, or end-to-end runtime verification was performed. Existing documentation and code comments were checked against executable paths where relevant. No application code was changed.

## Important implementation distinctions

`sigla-admin/src/pages/words/ManageWordBank.jsx` is retained legacy code: `App.jsx` routes users to `ManageWord.jsx` and redirects `/word_bank` to `/dataset`. Its obsolete controls should not be described as current portal features. Likewise, Android profile/authentication/notification classes and custom-category helper code do not by themselves establish accessible main-module features; the current navigation layouts expose the four main modules described in the draft.

The backend derives the public word list from recorded deployed-model word IDs, but this is not a transactional model/word-bank snapshot on the phone. In addition to failed-update cache invalidation, `getTrainedWordIds()` is called after training completes, so concurrent dataset edits can affect the recorded vocabulary. The revised scope describes the intended normal synchronization behavior without promising exact consistency under every failure or concurrent edit.

The supplied performance and hardware recommendations may originate from research outside the repository. They can be restored as study recommendations if supported by documented measurements, but should not be presented as requirements proven by the current code.
