3.4. Scope and Delimitation
The proponents developed SigLa: A Mobile Sign Language Translator Application that supports one-way communication from sign language users to non-sign language users. The system translates recognized sign language gestures into readable text and audible speech to assist users during daily interactions. The system stores all supported word information, gesture sample data, administrator account information, and system analytics in a centralized database to support translation updates and system monitoring.
The system has two (2) main end-users: the mobile user and the administrator. The mobile user uses the SigLa mobile application to perform sign-to-text and text-to-speech translation, while the administrator manages the system through a web-based platform. The mobile application does not require any account, login, or sign-up. It is used directly and anonymously, so all of its features are available to every user without registration.
The SigLa mobile application contains several modules that support the application's functions such as Main Interface, Word Bank, Translation History, and Settings. The SigLa Mobile Application serves as the primary interface for users. The application recognizes motion-based gestures, where each sign is captured as a short sequence of frames rather than a single still pose, so that both movement and hand shape contribute to recognition. The system converts recognized gestures into text and voice output, allowing the translated text to be spoken through the device's audio output to help communicate with non-sign language users. The system outputs individual words or predefined phrases and focuses on word-by-word translation instead of forming full sentences or continuous conversational translation.
The mobile application supports Filipino Sign Language (FSL) for common daily interactions. The application can assist in daily interactions such as introducing oneself, ordering food, buying items, asking for prices, giving numbers such as age, phone numbers, or addresses, requesting assistance, asking for directions, confirming information, and communicating basic needs such as expressing hunger or thirst, indicating pain or discomfort, requesting water, food, or medicine, asking to use the restroom, and expressing feelings such as being tired, scared, unwell, and additional words. The system supports a predefined set of words and phrases organized into categories. The number of supported words is subject to change as the administrator adds new words and expands the gesture recognition dataset over time.
The translation process occurs directly within the mobile application, allowing the system to function offline for gesture recognition and translation. The application requires an initial internet connection to download the base gesture recognition model. After this, gesture recognition can function offline. An internet connection is only required to download the gesture recognition model and to load the latest word bank content. When the device is connected to the internet, the application automatically checks for a newer gesture recognition model and downloads it only when a new version is available. The system provides no user access to model selection or rollback, as model management is handled exclusively by the administrator. Before replacing the currently active model, the system performs a model integrity verification to ensure that the downloaded model is complete and not corrupted. If the download fails or the gesture recognition model is found to be corrupted during transfer, the previously installed model remains active to ensure that gesture recognition continues to work. This ensures the system attempts to keep the model up to date.
When the user opens the SigLa Mobile Application for the first time, the system displays a brief onboarding tutorial that guides the user through the main features of the application. The tutorial introduces the Main Interface and explains how gesture detection works, how to use the Word Bank, and how to navigate the application using the retractable sidebar. The tutorial is shown only once upon first launch and can be skipped at any time. The tutorial display state is stored locally on the device. If the application is reinstalled or the app data is cleared, the tutorial will be shown again upon the next launch. Users may also revisit the tutorial at any time through the Settings module regardless of reinstallation status.
The main Interface serves as the primary translation screen where the user performs gesture recognition using the device camera. The interface automatically detects and translates sign language gestures as soon as the camera is active. After detecting a sign language gesture, the system displays the corresponding translated text on the screen in English along with its Filipino translation below it, and plays an audio output of the detected gesture. The user can also turn off the Filipino translation by pressing the Filipino translation button. To ensure accurate and stable detection, the system applies a two-second loading after each recognized gesture before accepting a new one, preventing unintended repeated detections and allowing time for the user to transition to another gesture. As a result of this loading, gestures typically require approximately 1 to 2 seconds to detect and translate. It includes a camera switch button that allows the user to switch between the front and rear camera for gesture detection, and an emergency button that, when pressed and held for two seconds, plays an audio alert saying "Help me" to quickly notify nearby individuals in urgent situations, preventing accidental activation while still allowing the feature to be used quickly when needed. A retractable sidebar is provided to serve as the navigation menu, allowing users to access modules such as word bank, translation history, and settings.

The word bank module allows users to view the list of words that can currently be translated by the application. It includes a category dropdown that allows users to filter entries based on their category, including introducing oneself, ordering food, buying items, asking for prices, giving numbers such as phone numbers, addresses or price, requesting assistance, asking for directions, confirming information, communicating basic needs, alphabets, numbers, and additional words. Selecting a sign entry plays an audio pronunciation of the corresponding word. It also displays a short demonstration video showing how the gesture is performed. These videos are generated from collected samples and are subject to administrator validation. The demonstration video is generated on the server from the approved gesture samples collected for that word and served to the app for playback, allowing users to visually learn how to perform each sign. Users may also personalize their word bank experience by creating custom categories to organize their most used or favorite gestures. A create category button allows the user to add a new category with a custom name, and gesture entries can be added to these custom categories by selecting them from the existing word list. Custom categories appear alongside the default categories in the category dropdown, allowing users to quickly filter and access the gestures they use most frequently. Users may also rename or delete their custom categories at any time. Custom categories and their entries are stored locally on the device. If the application is reinstalled or if the user switches to a different device, custom word bank categories and translation history are removed, as both are stored locally on the device. It has a retractable sidebar and also includes a back button that allows the user to return to the main interface.
The Translation History module allows users to view a record of all gestures that have been recognized and translated by the application during previous sessions. Each entry in the translation history displays the translated word, the confidence percentage of the recognition, and the time the translation was detected. Entries are grouped by date, with the most recent translations appearing at the top of the list. The translation history is stored locally on the device and can hold a maximum of two hundred (200) entries. Older entries are automatically removed once the limit is reached to manage storage. Users may delete individual entries by swiping left on an entry or by tapping the delete button, and may also clear the entire translation history at once using the clear all button, which requires confirmation before the entries are permanently removed. If a word that appears in a user's translation history is subsequently deleted from the system by the administrator, the corresponding history entry is retained on the device as a local record and is not automatically removed, as translation history is stored independently of the current system word database. Translation history is stored on the device and is cleared during reinstallation or when switching to a different device. The module includes a retractable sidebar and a back button to return to the main interface.
The Settings module allows users to configure application preferences such as volume level, voice type, and light or dark mode. The voice type setting allows users to select between a male or female voice for the text-to-speech audio output of recognized gestures. The system produces audio output in English, corresponding to the translated text displayed on the main interface. A reset to default button is provided to restore all settings to their original configuration. The module also includes an option to replay the onboarding tutorial for users who wish to review the application guide. All settings, including volume level, voice type, and light or dark mode, are saved locally on the device and are applied automatically whenever the application is opened. Because the settings are stored locally, they will not be retained if the application is reinstalled or if the user switches to a different device. It has a retractable sidebar, including a back button to navigate back to the main interface.
The SigLa administrator platform serves as the management interface of the system and requires an internet connection to access. Because the mobile application is used anonymously and has no user accounts, the platform's accounts belong only to system staff. It defines two (2) administrator roles: the super administrator, who manages the other administrator accounts, and the administrator, who focuses on managing the words and the gesture recognition model. The platform contains a Login page, Dashboard, Manage Administrator, Manage Word Bank, Manage Model, Reports and Analytics, Activity Logs, and Administrator Account.
The login page serves as the entry point to the administrator platform. To access the system, the administrator must enter a valid username or email address along with the correct password, then click the login button. If the administrator forgets their password, they can click the reset it here link to begin the password recovery process. The administrator must enter their registered email address, after which the system sends a six-digit verification code to that email. Once the correct code is entered, the administrator can set a new password and confirm it before clicking the reset password button to apply the change. A resend code option is available if the code is not received, subject to a one-minute cooldown between requests. After a successful password reset, the administrator is returned to the login page.
The dashboard serves as the first page the administrator sees after logging in. It provides a quick overview of what is happening in the system. At the top, it displays a summary section showing four key pieces of information: the total number of words in the system, the number of words waiting to be activated, the total number of gesture samples collected, and the current model version being used by the mobile application. Below the summary, a bar chart shows the number of new words added over time, which can be filtered by week, month, or year. Beside it, a list displays the accuracy of each trained model version, allowing the administrator to monitor whether the model performance is improving. At the bottom of the dashboard, a recent activity feed shows the latest events in the system, such as newly added words and newly activated words. Next to it, a list of words that have met the required number of samples and are ready to be activated is displayed, with a review button beside each entry that allows the administrator to directly open the corresponding word in the manage word bank module.
The manage administrator module contains the list of administrator accounts in the system and is accessible only to the super administrator. It allows the super administrator to view administrators, add new administrators, update administrator information, deactivate accounts, or delete accounts when needed. The administrator list table includes the name, username, email address, account status, date created, and action buttons. The add administrator button allows the super administrator to create a new administrator account by entering the administrator's name, username, email address, and password. The super administrator is responsible for ensuring the accuracy of the email address entered, as it will be used for verification codes in password recovery. The deactivate button temporarily disables an administrator account so it can no longer be used to sign in, while the reactivate button restores a previously deactivated account. The edit button allows the super administrator to update administrator information, and the delete button permanently removes an administrator account from the system.
The Manage Word Bank module allows administrators to control and maintain all the words available in the system. Through this module, the admin can add, edit, delete, and manage gesture data for each word. When adding a new word, the admin uses the add word button and fills in the word itself, a short description, the number of hands required, either one or two, a category from the predefined list of FSL interaction categories, and an optional Filipino translation of the word. Words added manually contain no gesture samples at first, so the administrator must upload samples before the word can be activated. The administrator can also edit existing words to update their spelling, description, number of hands, category, or Filipino translation. If a word is no longer needed, the admin can delete it, which also removes all its related gesture samples. The admin can upload gesture samples directly to any word, especially for words that were manually added. These samples are uploaded as a batch of gesture recording videos, and the system automatically processes each recording using the MediaPipe landmark detection framework to extract the hand and upper-body landmark coordinates for every frame. All samples uploaded by the admin are automatically marked as approved and counted toward the required number of samples. For a word to be activated, it must meet the minimum sample requirement of at least twenty-five (25) approved gesture sequences.
The admin can generate a demonstration video using the approved samples. This video is created by the system's machine learning component and shows how the gesture is performed. The admin can generate a video at any time, even before reaching the required number of samples, to check if the gesture looks correct. Videos can be generated for a single sequence or for multiple selected sequences at once. After generating, the admin can preview the video and adjust its playback speed. Once the word has met the required number of approved samples, the admin can click set as word bank video to publish the video to the mobile app. This action activates the word, and it will appear in the mobile application after it reloads.
The module also allows the admin to review the gesture samples of a word. By opening the gallery of a word, the admin can see all of its samples along with the status of each sample. When checking samples, the admin verifies that each one meets the following quality criteria: the hand gesture must be clearly visible, the gesture formation must be correct, the hand must be fully visible and not cut off, and the camera framing must be appropriate. Samples that do not meet these criteria can be removed so that only quality samples are retained for the word.
The manage model module contains the list of model versions used for gesture recognition. It allows the administrator to manage the machine learning models in the system. The model list table shows the model version, accuracy, date created, and action. To train a new model, the administrator can click the train button, which starts the training process using the approved gesture datasets. After training, the administrator can click the test button to check the accuracy of the model before deploying it in the application. The administrator can activate a model by clicking the deploy button so it can be used in the mobile application. If the current model causes errors or has lower accuracy, the administrator can click the revert button to return to a previous stable model version. The system retains all previously trained model versions in the database, allowing the administrator to revert to any prior version. Model versions can only be deleted manually by the administrator using the delete button, and at least one deployed model version must remain active in the system at all times.
The reports and analytics module provides administrators with an overview of system activity. It displays the total number of words in the system, the number of words waiting to be activated, the number of gesture samples per word, the number of new words added over time, and the accuracy of each trained model version. It includes filter buttons for week, month, and year that allow administrators to adjust the displayed data range to monitor how the word bank and model performance grow over time. A generate report button is also available, allowing administrators to export a summary report of the system activity in PDF format. Before generating, the administrator can select which specific overview to include in the report, such as word statistics, gesture sample counts, word growth trends, or model accuracy, and apply the week, month, or year filter to define the data range covered by the report. This allows administrators to produce focused and relevant reports for record-keeping, performance evaluation, and system monitoring purposes.
The activity logs module provides an audit trail of the actions performed within the administrator platform, allowing administrators to track who made a change and when it was made. The system automatically records an entry whenever an administrator performs a significant action, such as adding, editing, deleting, or activating a word, uploading gesture samples, training, testing, deploying, or reverting a gesture recognition model, creating, editing, deactivating, or deleting an administrator account, and signing in to the platform. Each log entry captures the administrator who performed the action, the type of action, the affected item, a short description of the change, and the date and time it occurred. The module displays the entries in a table ordered from most recent to oldest and provides filters for the action type, the affected item, and the date range so administrators can quickly locate specific events. The activity logs are read-only and cannot be edited or deleted from the platform, preserving the integrity of the record. All administrators can view the activity logs to monitor system changes and maintain accountability. The module includes filter controls and pagination to browse through the recorded history.
The Administrator Account module contains the administrator's account information such as username and email address. The administrator can update these details by clicking the edit profile button. After editing the information, the administrator can click the save button to apply the changes. It also has a change password button that allows the administrator to update the account password. To change the password, the administrator must first verify their email address by entering the correct six-digit (6) verification code before inputting a new password. A save button is provided to confirm and apply the new password.
The system architecture consists of the SigLa mobile application, SigLa administrator platform, SigLa Backend Server, SigLa Machine Learning Component, and PostgreSQL Database. The mobile application communicates with the backend server to fetch the latest word bank content and model updates, and does not require any user account to do so. The backend server acts as the bridge between the mobile application, the administrator platform, the machine learning module, and the database. The machine learning module handles gesture recognition model training, testing, deployment, and demonstration video generation, while the database stores system data such as administrator accounts, words, gesture samples, and model information. The system follows a client-server architecture where the mobile application handles gesture recognition locally using a downloaded TFLite model, while the backend server manages word and model management and model updates through a REST API.
The system is developed using Kotlin for the Android mobile application, React.js for the web-based administrator platform, Node.js with Express.js for the backend server, Python for the machine learning component, and PostgreSQL as the database management system. The system also uses Supabase as the cloud platform for database hosting and storage. Development tools used include Android Studio, Visual Studio Code, Postman, and GitHub.
The proponents recognize that gesture recognition performance can be influenced by device specifications and environmental conditions, and the system is designed to adapt and perform effectively within these factors. Devices with higher hardware capabilities may enhance performance. The system aims to provide accurate translations, but occasional inaccurate translations may occur. Recognition results may also be influenced by environmental factors such as insufficient lighting, a dirty or damaged camera lens, camera obstruction, or excessive distance between the camera and the hand gesture. The system supports basic Filipino Sign Language (FSL) gestures. While the main interface displays the translated text only in English and Filipino. The SigLa produces individual words or set phrases only. The English translation is provided solely to make the recognized gesture more broadly understandable to a wider audience, as many FSL gestures correspond to concepts that are more commonly expressed in English. The underlying gesture recognition, the gesture dataset, and the entire translation process are based entirely on FSL. The system recognizes only sign gestures, with each recognized gesture mapped to a predefined word or phrase based on the trained dataset. Variations in hand structure, such as incomplete or irregular fingers, may affect the system's recognition accuracy. The system is designed to improve gesture recognition within its capabilities and to continuously support clear and effective gesture-based communication.
For optimal recognition, the recommended distance between the camera and the hand gesture should not exceed 0.5 meters to ensure reliable gesture recognition. The system supports left-handed and right-handed users, as well as gestures that require one or both hands. The system supports gesture recognition for up to two hands, accommodating both one-handed and two-handed gestures.
The system requires a stable internet connection with a minimum speed of 10 Mbps for the mobile features that require server communication, such as loading the latest word bank content and downloading model updates. The mobile application recommended minimum specifications include a 13-megapixel camera, a minimum of 6GB of RAM to ensure stable simultaneous operation of the camera, landmark detection framework, and gesture recognition models, and must run on Android version 7.0 (Nougat) or higher to ensure compatibility and proper performance. The SigLa Mobile Application is developed exclusively for the Android platform and does not support iOS or any other mobile operating system.
